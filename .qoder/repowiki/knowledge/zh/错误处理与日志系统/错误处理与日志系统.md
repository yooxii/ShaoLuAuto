## 错误处理架构概述

该 WPF 自动化烧录工具采用混合式错误处理策略，结合结构化异常抛出、NLog 日志记录和 UI 层错误展示，形成从底层操作到用户界面的完整错误处理链路。

## 核心系统与工具

**日志框架**: 使用 NLog 进行结构化日志记录，配置文件 `NLog.config` 定义了文件和控制台双输出目标，支持异常信息格式化输出。

**执行日志持久化**: 通过 `ExecutionLogService` 使用 FreeSql + SQLite 存储步骤执行历史，实现可查询、可筛选的执行审计。

**UI 错误展示**: 通过 `StepExecutionResult.ErrorMessage` 字段和 `ShowErrorPopup` 属性控制错误弹窗显示。

## 关键文件与组件

- **App.xaml.cs**: 应用级异常捕获，在 `OnStartup` 中统一记录启动异常
- **Services/ExecutionLogService.cs**: 执行日志服务，所有数据库操作都包含 try-catch 保护
- **Utils/Autogui.cs**: 图像识别和自动化操作的核心类，大量使用异常表示操作失败
- **Models/StepExecutionResult.cs**: 标准化的执行结果模型，包含错误信息字段
- **Converters/AutomationStepJsonConverter.cs**: JSON 序列化时的自定义异常处理

## 架构设计与约定

### 1. 异常抛出策略
- 业务逻辑错误：直接抛出 `Exception` 或特定异常类型（如 `ArgumentNullException`）
- 资源验证错误：抛出 `ArgumentException`、`InvalidOperationException` 等语义化异常
- JSON 转换错误：抛出 `JsonException` 并附带详细错误信息

### 2. 异常捕获模式
- **服务层**: 使用 try-catch 包裹外部依赖调用，记录错误后返回默认值或空结果
- **UI 层**: 通过 `ErrorMessage` 字段传递错误信息，由 ViewModel 决定如何展示
- **应用级**: 在 `App.OnStartup` 中捕获未处理异常，确保程序健壮性

### 3. 日志记录规范
- 所有 I/O 操作、网络请求、数据库操作都记录详细日志
- 使用 `logger.Error(ex, "message")` 格式记录异常堆栈
- 异步日志写入避免阻塞主流程

### 4. 错误传播机制
- 底层方法抛出异常 → 中间层捕获并记录 → 上层根据业务逻辑决定是否继续
- 用户可见的错误通过 `StepExecutionResult.ErrorMessage` 向上层传递
- 内部错误仅记录日志，不中断业务流程

## 开发者应遵循的规则

1. **参数验证**: 在方法入口处验证参数，对无效输入抛出明确的异常类型
2. **外部依赖保护**: 所有可能失败的外部调用（文件、网络、数据库）都要有 try-catch 保护
3. **日志完整性**: 关键操作必须记录成功和失败两种情况的日志
4. **用户友好**: 面向用户的错误信息要清晰易懂，避免技术术语
5. **资源清理**: 使用 finally 块确保资源正确释放，特别是文件句柄和内存对象
6. **异常分类**: 区分可恢复错误和致命错误，前者记录警告，后者记录严重错误
