## 构建系统与工具链
- 构建引擎：MSBuild（.csproj 项目文件），通过 Visual Studio / .NET Framework SDK 驱动。
- 解决方案入口：根目录 `ShaoLu.slnx`，聚合 ShaoLu（WPF 应用）与 NUnitTest（单元测试）两个项目。
- 目标框架：.NET Framework 4.8（WinExe），运行时标识 `win-x64`，默认平台目标为 x64。
- 包管理：NuGet PackageReference，依赖包括 OpenCvSharp4、TesseractOCR、NLog、EPPlus、CommunityToolkit.Mvvm、WPFLocalizeExtension 等。
- 测试框架：NUnit 4.6.1 + NUnit3TestAdapter，FlaUI.UIA3 用于 UI 自动化测试。

## 关键构建文件与配置
- `ShaoLu.slnx`：定义 Any CPU 与 x64 两种平台配置，并将 ShaoLu 项目强制绑定到 `*|x64`，确保 WPF 桌面应用以 x64 输出。
- `ShaoLu/ShaoLu.csproj`：主项目构建配置，包含 Debug/Release、AnyCPU/x64 多配置项，设置语言版本为 preview，启用确定性构建（Deterministic=true），配置 ClickOnce 发布路径与自动更新策略。
- `NUnitTest/NUnitTest.csproj`：测试项目，引用主项目并通过 ProjectReference 建立依赖关系。
- `ShaoLu/App.config`、`ShaoLu/NLog.config`：运行时配置文件，随构建复制到输出目录。

## 架构与约定
- 双平台构建：通过 slnx 统一约束 ShaoLu 始终输出 x64，避免 AnyCPU 在 32/64 位环境下的歧义。
- 资源与本地化：resx 文件通过 PublicResXFileCodeGenerator 自动生成 Designer.cs，支持 en-US、zh-CN、zh-TW 多语言。
- 第三方依赖：
  - TesseractOCR 使用 ExcludeAssets="compile;runtime" 排除编译期依赖，运行时由 tessdata 目录提供。
  - WPFDevelopers.dll 通过 HintPath 引用 Reference 目录下的本地 DLL。
  - OpenCvSharp4.runtime.win.slim 提供 Windows 原生运行时。
- 输出结构：bin\Debug、bin\Release、bin\x64\Debug、bin\x64\Release 四套输出路径，tessdata 与 NLog.config 复制到输出目录。
- 应用程序清单：生成 manifest，使用临时证书文件 ShaoLu_TemporaryKey.pfx，但未启用签名（SignManifests=false）。

## 开发者应遵循的规则
- 新增代码文件需手动添加到 csproj 的 ItemGroup 中（当前项目未使用 SDK 风格的隐式包含）。
- 保持 PlatformTarget 为 x64，避免引入 32 位原生依赖导致运行失败。
- 修改 NuGet 包后需确保运行时依赖（如 tessdata、OpenCV 原生库）随构建正确复制。
- 多语言资源更新 resx 后需重新生成对应的 Designer.cs 文件。
- ClickOnce 发布路径硬编码在 csproj 中，跨环境发布时需调整 PublishUrl 与 UpdateUrl。
- 测试项目通过 ProjectReference 引用主项目，无需单独打包即可运行 NUnit 测试。
